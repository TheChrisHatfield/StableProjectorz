## Learned User Preferences

- Treat Context_Ref and similar reference exports as read-only documentation of the original source; do not edit them when fixing the Unity project—use them only to understand legacy behavior.
- When adjusting Unity UI padding, use `RectOffset` in the order left, right, top, bottom consistently across the paint and ribbon code.
- After runtime creation or rebuild of brush preset sections, re-apply a single flush layout pass (VLG spacing, header `LayoutElement` heights, grid anchors) so thumbnails sit tight under the collapsible header.

## Learned Workspace Facts

- Python add-ons connect to Unity over TCP JSON-RPC on port 5555 (`Addon_SocketServer`, wired from `Addon_MGR`); `Addon_HttpServer` optionally exposes REST endpoints that delegate to the same JSON-RPC handler.
- IL2CPP player builds can assert on `Resources.GetBuiltinResource` in add-on UI (`AddonManager_UI`); prefer explicit fallback sprites or project assets instead of built-in resource lookup on those paths.
- Release builds are normally produced from the Unity Editor (e.g. Build and Run); expect output under `Build_IL2CPP` such as `StableProjectorz.exe`, not an assumed CLI build unless Unity is invoked with a known editor path.
- Runtime brush painting uses `BrushAlphas_MGR.GetCurrentBrushStampTexOrFallback()` as the canonical stamp source for the paint pipeline.
- ABR import and decode edge cases (1-bit stride alignment, RLE, v6+ samp blocks, consumed-byte caps) are documented under `docs/` including `docs/ABR_DECODE_REFERENCE.md`.
- Viewport paint layers reach Stable Diffusion via UV accumulation, material updates, and the content camera capture path; if layers appear on meshes but not in SD payloads, suspect capture-time early-outs (e.g. save guards skipping layer apply) or GPU ordering—ensure layer composite and material updates complete before content-camera render or readback.
- 3D mesh picking reads one pixel from the mesh-ID render target at the cursor (`ClickSelect_Meshes_MGR`), decodes a mesh id, and toggles selection through `ModelsHandler_3D`; occasional expensive CPU readback is acceptable because it runs on click only.
- Shared responsive/tokens for runtime uGUI: `ProjectUiScale` (`Assets/_gm/_Core/UI (reusable)/ProjectUiScale.cs`) — 8px `Space(n)`, Tailwind-aligned width breakpoints in canvas reference px, `GetBand`, `ClampModalSize`. Add-on ribbon tabs use `CommandRibbon_UI` / `TabsGroup_UI` (runtime strip layout + `HarmonizeStripTabTypography`); reuse `ProjectUiScale` for new overlays.
- Paint tab **+ Layer** wiring: a global `FindObjectOfType<PaintTab_LayersPanel_UI>` can bind the wrong instance if more than one panel exists—the button you click may not be the panel that receives `AddLayer`. Prefer resolving the layers panel from the Paint tab layout (`LayersSection` / collector hierarchy), wiring before and after row reparent, and **deferring** layer list rebuild at least one frame so the control under the pointer is not destroyed mid-click. `CommandRibbon_UI.On_Paint_Toggle` may need `CollectNow()` on the paint collector so refs refresh when switching to Paint.
- **Smudge routing** (`SmudgeStrokeRouter.Build`): do not return an empty plan whenever `hasLayerStack && !LayerSmudgeGateOpen`—that blocks no-stack / mesh / art paths. Only no-op when the stroke targets the **active layer `Content`** and the gate is closed. Mesh-domain smudge when `ReferenceEquals(layerPaintTarget, meshAccumulation)`; art-domain when the paint target shares the **same texture array** as the art UV wrapper (not `SameShape` alone). **`Inpaint_MaskPainter`**: use `SMUDGE_LAYER_PAINT_ONLY` / omit accumulation copy only when the router supplies **no** underlay (`smudgeAcc == null`); otherwise keep layer-over-accum sampling so UV gen in the accumulation contributes under thin layer alpha (`ApplyBrushStroke_IntoMask.compute`).
- **Camera pins / MMB pan**: perspective-center pan goes through pin grab in `CamerasMGR_PinsZone_UI` (`GrabPin_maybe` / `DragPin_maybe`). Do not cap `FindNearestPin` with a small max distance—outside that radius MMB never starts a drag and pan feels dead. **POV digit “1” on mesh** can come from pin TMP labels (`FadeOutUnlessPersist_UI` on pins) or from the **multi-projection** path when `GenData_Masks.numPOV` does not match how many view cameras are active—`ProjectorCameras_RenderHelper` branches on `numPOV`. This fork matches **upstream OG** multiview wiring: **`MultiView_Ribbon_UI.LateUpdate`** drives **`UserCameras_MGR.EnableExactly_N_ViewCameras`** when the slider intent changes; there is **no** separate archive-wide POV/mask auto-sync API—do **not** resurrect removed helpers (`SyncPOV_enableFlags…`, `RefreshPovMasksForCurrentViewCameraCount`, `SyncAllSdProjTextures…`, per-frame `MaybeSync…`) without re-reading `continual-learning/multiview-pov-mask-sync.md` and reconciling with OG. Avoid calling **`ProjectorCamera.Init`** just to “refresh” masks—it rebinds `_myMeshes` to **current** selection and can orphan projection binding.
- **Single-layer visibility**: for `Layers.Count == 1`, `ApplyColorLayer_To_UV_Textures` / `GetLayerCompositeOrFallback` must respect `ActiveLayer.Visible` (or the sole layer’s visibility); otherwise a hidden layer still composites to the mesh / SD paths.
- **Paint on mesh during / after SD**: `Objects_Renderer_MGR.Apply_InpaintSketch_ColorLayer` composites stack `Content` onto `_accumulation_uv_RT`. If that blit is skipped while `ReRenderAll_soon` keeps clearing/rebuilding accumulation (e.g. progress ticks), the mesh looks paint-free even though layer RTs are intact—when any layer stack exists (`Count >= 1`), keep compositing; do not rely on `allowed_to_showBrushMask()` alone for the single-layer case after generation ends.
- **Input / pen vs UI**: `EventSystemEnsureInputSystemUIModule` only adds `InputSystemUIInputModule` when a `StandaloneInputModule` is present—EventSystems with neither stay unwired. `SliderStylusSupport` on runtime sliders can double-drive with `InputSystemUIInputModule`. Unfiltered `EventSystem.RaycastAll` “over UI” checks (viewport listeners, optional pen/mode guards on the inpaint ribbon) treat any graphic hit as blocking—invisible `raycastTarget` regions often explain intermittent pen or viewport behavior.
- **Main viewport hover vs add-on modal**: `MainViewport_UI.isCursorHoveringMe` / `IsCursorInside_my_width` should **not** early-return on `AddonManager_UI.IsModalOpen` alone (OLD_TEST_REPO had no such gate). Pin/MMB grab in `CamerasMGR_PinsZone_UI.GrabPin_maybe` requires `isCursorHoveringMe()`; a blunt `IsModalOpen` false can stall pan when modal state is wrong. Prefer the add-on overlay path: top `Canvas` sort, fullscreen blocker with **`MainViewport_RaycastBlocker`** so `MainViewport_UI_EventListener.TryRaycastTowardsSelf()` reflects the modal (`AddonManager_UI` comments). **`AddonManager_ModernArchive/README.txt`** notes re-applying viewport hooks when merging modern add-on UI—`IsModalOpen` there was redundant hardening, not the only isolation layer.
- **Editor diagnostic (viewport vs modal)**: On `MainViewport_UI`, enable **`_logAddonModalViewportDisagreementsInEditor`** to log (throttled) when **`AddonManager_UI.IsModalOpen`** is true but **`TryRaycastTowardsSelf()`** is still true—signals possible click-through or canvas/blocker ordering issues (no-op in player builds).
- **OLD vs current (camera pan feel)**: `git diff` shows **`CamerasMGR_PinsZone_UI` `DragPin_maybe` / `[0,1]` clamp unchanged** vs OLD_TEST_REPO; differences that affect feel cluster **`MainViewport_UI` hover**, **`Global_Skeleton_UI`** (side-panel collapse / layout rebuild → `innerViewportRect` geometry), and **`UserCameras_MGR`** (`NearestToCursor`, view-camera enable caps).
- **Paint undo vs Stable Diffusion**: `PaintUndo_MGR` clears history **only** when `PaintLayerStack_MGR.OnLayerStackStructureChanged` fires (see `PaintUndo_MGR.OnLayerStackStructureChanged_ClearHistory`) — e.g. **resolution/UDIM change** (`EnsureResolution` when `w×h×slices` changes), **remove/move layer**, or **full stack `Load`**. Finishing an SD generation updates **icon / `GenData`** textures, not that event chain by itself, so **stroke undo stacks usually remain** and Ctrl+Z still restores **layer `Content`** pixels captured before each stroke. If paint resolution changes mid-session (init textures / img2img boost / new UDIM count), undo is wiped intentionally. Undo is **not** a history of SD artboard revisions—only viewport paint buffers (plus non-stack targets like projection masks per `PaintUndoNonStackTarget`).
